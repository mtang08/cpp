## Question: why can a const rvalue call a copy constructor taking `const Payload&`?

`const Payload&` is a const lvalue reference, but it can bind to both lvalues and rvalues. The word "lvalue" in the reference type does not restrict it to accepting only lvalue expressions. A non-const lvalue reference (`Payload&`) cannot normally bind to an rvalue.

`std::move` preserves constness, so applying it to a `const Payload` produces `const Payload&&`. The move constructor taking `Payload&&` cannot accept that expression because doing so would discard constness. The copy constructor taking `const Payload&` can bind to it, making copying the viable choice. Reference binding itself does not copy; the selected copy constructor performs the copy.
